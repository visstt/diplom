# Техническое задание

## Структура и функциональность административной панели

### Назначение
Административная панель предназначена для управления каталогом товаров, перечнем услуг, пользователями системы и аналитикой. Доступ к панели предоставляется только пользователям с ролью `admin`.

### Точка входа
- URL: `/admin`
- Доступ: только авторизованный пользователь с ролью `admin`
- При отсутствии прав выполняется редирект в профиль пользователя `/profile`

### Технологическая основа
- Frontend: `React`, `react-router-dom`, `react-hot-toast`
- Backend: `NestJS`, `Prisma`, `PostgreSQL`
- Загрузка изображений: `Multer`
- Визуализация аналитики: `Recharts`

## Детализация разделов

### 1. Общий доступ и поведение панели

#### Функции
- Проверка роли пользователя при открытии страницы.
- Блокировка доступа для неадминистраторов.
- Переключение между вкладками без перезагрузки страницы.
- Показ уведомлений об успешных и неуспешных операциях.

#### Содержимое
- Заголовок страницы: `Админ-панель`
- Навигационные вкладки:
  - `Товары`
  - `Услуги`
  - `Пользователи`
  - `Аналитика`

---

### 2. Раздел «Товары»

#### Назначение
Раздел предназначен для полного управления каталогом товаров.

#### Реализованные функции
- Просмотр списка товаров.
- Создание нового товара.
- Редактирование существующего товара.
- Удаление товара.
- Отображение изображения, названия, цены и категории в списке.

#### Поля формы товара
- Название
- Цена
- Описание
- Категория
- Преимущества
- Функциональные возможности
- Изображение

#### Особенности заполнения
- Поля `Преимущества` и `Функциональные возможности` вводятся построчно.
- При сохранении строки преобразуются в массивы.
- Для товара обязательно наличие:
  - названия
  - цены больше `0`
  - категории
  - изображения

#### Валидации
- Нельзя сохранить товар без названия.
- Нельзя сохранить товар с ценой `<= 0`.
- Нельзя сохранить товар без категории.
- Нельзя сохранить товар без изображения.

#### API
- `POST /products` — создание товара
- `PATCH /products/:id` — обновление товара
- `DELETE /products/:id` — удаление товара
- `GET /products` — получение списка товаров

---

### 3. Работа с изображениями товаров

#### Назначение
Подсистема предназначена для загрузки и привязки изображений к товарам.

#### Реализованные функции
- Выбор изображения через input.
- Перетаскивание изображения в область загрузки.
- Предпросмотр загружаемого файла.
- Замена изображения.
- Удаление выбранного изображения перед сохранением.

#### Ограничения
- Допустимые форматы:
  - `jpg`
  - `jpeg`
  - `png`
  - `gif`
  - `webp`
- Максимальный размер файла: `5 MB`

#### API
- `POST /upload/image`

#### Результат загрузки
- Сервер возвращает:
  - имя файла
  - относительный URL вида `/uploads/<filename>`

---

### 4. Раздел «Услуги»

#### Назначение
Раздел предназначен для управления перечнем услуг компании.

#### Реализованные функции
- Просмотр списка услуг.
- Создание новой услуги.
- Редактирование существующей услуги.
- Удаление услуги.

#### Поля формы услуги
- Название
- Цена
- Описание

#### Валидации
- Название обязательно.
- Цена должна быть больше `0`.

#### API
- `POST /services` — создание услуги
- `PATCH /services/:id` — обновление услуги
- `DELETE /services/:id` — удаление услуги
- `GET /services` — получение списка услуг

---

### 5. Раздел «Пользователи»

#### Назначение
Раздел предназначен для администрирования пользователей системы.

#### Реализованные функции
- Просмотр списка пользователей.
- Отображение краткой информации по каждому пользователю.
- Назначение роли `admin`.
- Снятие роли `admin`.
- Просмотр детальной карточки пользователя.
- Просмотр товаров, купленных пользователем.

#### Отображаемые данные пользователя
- Имя и фамилия
- Email
- Телефон
- Роль
- Дата регистрации
- Количество товаров

#### Ограничения
- Администратор не может изменить собственную роль.

#### Детальная карточка пользователя содержит
- Роль пользователя
- Телефон
- Дату регистрации
- Список покупок
- Название товара
- Количество
- Стоимость
- Дату покупки
- Изображение товара, если оно есть

#### API
- `GET /users` — получение всех пользователей
- `PATCH /users/:id/role` — изменение роли пользователя
- `GET /users/:id/purchases` — получение списка покупок пользователя

---

### 6. Раздел «Аналитика»

#### Назначение
Раздел предназначен для просмотра статистики по товарам и покупательской активности.

#### Реализованные функции
- Просмотр сводных карточек метрик.
- Просмотр графика топа товаров по покупкам.
- Просмотр графика топа товаров по просмотрам.
- Просмотр распределения покупок по товарам.
- Просмотр динамики продаж за последние 30 дней.
- Просмотр таблицы полной статистики по товарам.
- Обновление данных по кнопке.

#### Сводные показатели
- Общее количество товаров
- Общее количество просмотров
- Общее количество покупок
- Среднее количество просмотров на товар

#### Разделы аналитики
- `Обзор`
  - топ-5 товаров по покупкам
  - топ-5 товаров по просмотрам
- `Покупки`
  - круговая диаграмма распределения покупок
  - график динамики продаж
- `Просмотры`
  - горизонтальная диаграмма просмотров и покупок
- `Таблица`
  - полная статистика по всем товарам

#### Показатели по товару
- ID
- Название
- Категория
- Цена
- Количество просмотров
- Количество покупок
- Конверсия в процентах

#### API
- `GET /products/analytics` — общая аналитика
- `GET /products/popular?limit=10` — популярные товары
- `GET /products/:id/stats` — статистика конкретного товара
- `POST /products/:id/view` — инкремент просмотра товара

## Серверные ограничения доступа

### Доступ только для администратора
Следующие операции доступны только пользователю с ролью `admin`:
- создание товара
- редактирование товара
- удаление товара
- просмотр общей аналитики
- просмотр статистики товара
- создание услуги
- редактирование услуги
- удаление услуги
- просмотр списка пользователей
- изменение роли пользователя
- просмотр покупок пользователя
- загрузка изображений

### Дополнительные ограничения
- Пользователь с ролью `admin` не может оформлять заказы через `checkout`.
- Пользователь с ролью `admin` не может изменить свою собственную роль через админ-панель.

## Сценарии использования

### Сценарий 1. Добавление товара
1. Администратор открывает вкладку `Товары`.
2. Нажимает кнопку создания товара.
3. Заполняет обязательные поля.
4. Загружает изображение.
5. Указывает преимущества и функциональные возможности.
6. Сохраняет запись.

### Сценарий 2. Изменение роли пользователя
1. Администратор открывает вкладку `Пользователи`.
2. Находит нужного пользователя в списке.
3. Нажимает кнопку смены роли.
4. Подтверждает действие.
5. Получает уведомление об успешном изменении.

### Сценарий 3. Анализ статистики товаров
1. Администратор открывает вкладку `Аналитика`.
2. Просматривает сводные показатели.
3. Переключается между разделами `Обзор`, `Покупки`, `Просмотры`, `Таблица`.
4. Анализирует популярность, просмотры и конверсию товаров.

Реализованная административная панель обеспечивает:
- централизованное управление товарами и услугами;
- контроль пользователей и их ролей;
- просмотр истории покупок;
- визуальный анализ просмотров и продаж;
- безопасный доступ на основе роли администратора;

Функциональность панели покрывает основные административные сценарии для сопровождения каталога и контроля активности пользователей в системе.
